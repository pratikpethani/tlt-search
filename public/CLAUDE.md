Project: tlt-search, an original WooCommerce live product search plugin built on Loupe PHP (SQLite). Goal: match the useful features of Advanced Woo Search and beat it on search quality, merchandising and analytics. Study competitor behavior, never copy its code.
Code layout: namespace TLTSuite\TLTSearch, PSR-4 in src/. Search/ (LoupeEngine, SearchManager, FacetBuilder, QueryPreprocessor), Indexing/, Woocommerce/ (ProductDocumentMapper, ProductSync, SearchIntegration), API/ (REST tlt-search/v1), Analytics/, Synonyms/, Merchandising/. Front end: Alpine.js in public/; admin in admin/.
Rules: Use Loupe natively (filters, facets, sorting, ranking) before writing PHP post-processing. Any change to searchable or filterable attributes or stop words needs a rebuild path and a note to the user. Validate REST input, escape output, use nonces and capability checks in admin. Follow WordPress coding standards and the existing admin style. Flag any feature that affects the ~50k-document Loupe limit.
Workflow: Read the relevant files first. Propose before large changes. Explain results in plain language for a non-developer, answer first. Say what was read versus inferred. Keep research/awsearch-vs-tlt-search.md updated as features ship.
Roadmap order: dropdown polish, native Loupe filters and sort, field settings, index reliability, multilingual plus block/Elementor, then integrations.
